# 检视报告

## 概要

检视 `url` 参数支持数组（多 URL 并行抓取）的变更。涉及 `params.py`（类型与校验）、`server.py`（并行执行逻辑）、`test_read_image_download.py`（测试污染修复）、`test_workflow.py`（新增 7 个测试）及 README schema 同步。整体实现简洁清晰，向后兼容良好，测试覆盖充分，无阻塞问题。

## 需求对齐

- ✅ `url` 支持 `Union[str, List[str]]`，单 URL 行为完全不变（同一 handler 的 `isinstance` 分支）
- ✅ 多 URL 使用 `asyncio.gather` 并行执行，失败不影响其他 URL
- ✅ 返回格式为 `{"results": [...], "results_total", "results_succeeded", "results_failed"}`
- ✅ `elicit` + 列表 → 校验时报错；`cursor` + 列表 → 校验时报错
- ✅ 截图的 base64 嵌入 + Image block 返回
- ✅ `test_read_image_download.py` 测试污染已修复（只 pop server 模块）
- ✅ Schema 文档已同步到 README

## 阻塞问题

无。

## 非阻塞问题

| ID | 位置 | 问题 | 建议 |
|----|------|------|------|
| N1 | `server.py:104-108` | 多 URL 下所有结果的 screenshot bytes 先 base64 嵌入 JSON、再解码为 Image blocks，会同时存在两份内存副本（b64 string + raw bytes）。大量大截图可能导致 OOM。 | 可在收集 screenshots 阶段直接保持 bytes 格式，不做额外编解码。当前做法是为使 JSON 中保留 screenshot 字段，但如果 JSON 中的 screenshot 字段并非必须，可以优化。 |
| N2 | `server.py:advanced_fetch` 函数签名 | `cursor`、`max_length`、`output_to_file` 等 `AdvancedFetchParams` 字段未出现在 handler 函数参数中，导致这些参数无法从 MCP 客户端传入（会被静默忽略）。这是预存问题，非本变更引入，但多 URL 场景下用户可能希望传 `max_length`。 | 考虑将缺失的参数补全到 handler 签名中。非本变更范围，可单独处理。 |
| N3 | `params.py:29-36` | `UrlParam` 类型标注为 `Union[str, List[str]]`，列表泛型使用 `typing.List` 而非 `list`（Python 3.9+ 内置泛型）。项目整体风格不统一。 | 考虑全局统一为 `list[str]`（Python 3.9+），但非本变更引入，可单独处理。 |
