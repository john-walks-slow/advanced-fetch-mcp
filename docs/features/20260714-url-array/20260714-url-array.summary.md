# url 支持传数组

## 背景

`advanced_fetch` 工具的 `url` 参数只接受单个 URL/refid。用户需要批量抓取多个页面时需要多次调用，效率低。

## 改动

### 核心变更

- **`params.py`**: `UrlParam` 从 `str` 改为 `Union[str, List[str]]`
  - 新增校验：空列表、elicit + 列表、cursor + 列表均报错
- **`server.py`**: 新增 `_execute_multi_url()` 函数
  - 单 URL 走原路径，完全向后兼容
  - 多 URL 用 `asyncio.gather(return_exceptions=True)` 并行执行
  - 返回 `{"results": [...], "results_total": N, "results_succeeded": N, "results_failed": N}`
  - 截图在 JSON 中以 base64 嵌入，同时返回 Image blocks

### 并发与容错

- 并行执行，失败隔离（`return_exceptions=True` 保证单个 URL 失败不影响其他）
- 站点限流（`_wait_for_site_rate_limit`）在每个 `fetch_url` 内部处理，天然隔离

### 修复的 pre-existing issue

`test_read_image_download.py` 中 `_import_server()` 会 purge 所有 `advanced_fetch_mcp.*` 模块再重新 import，导致 `test_workflow.py` 中的 mock 失效。改为只 pop server 模块，与 `test_server_schema.py` 的做法一致。

## 测试

新增 8 个测试（现共 29 个 workflow 测试，全量 195 个），覆盖：
- 多 URL 并行成功、部分失败、截图
- 空列表报错、elicit + 列表报错、cursor + 列表报错
- `output_to_file` + 多 URL
- 单 URL 行为不变

## 检视结果

准入。4 个建议修改（S1-S4）已全部处理。
